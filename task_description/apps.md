Обзор директории apps/
В этой директории находится система управления умным домом ("Smart Home"), состоящая из двух связанных приложений:
🏠 1. Smart Home API (smart_home/)
Основное приложение - это REST API для управления сенсорами умного дома:
Что делает:
Управляет сенсорами умного дома (создание, чтение, обновление, удаление)
Хранит данные о сенсорах в PostgreSQL базе данных
Интегрируется с внешним температурным API для получения актуальных данных
Предоставляет REST API эндпоинты для работы с сенсорами
Основной функционал:
GET /api/v1/sensors - получить все сенсоры
GET /api/v1/sensors/:id - получить конкретный сенсор
POST /api/v1/sensors - создать новый сенсор
PUT /api/v1/sensors/:id - обновить сенсор
DELETE /api/v1/sensors/:id - удалить сенсор
PATCH /api/v1/sensors/:id/value - обновить значение сенсора
GET /api/v1/sensors/temperature/:location - получить температуру по локации
Технологии:
Go + Gin Framework
PostgreSQL для хранения данных
Docker контейнеризация
🌡️ 2. Temperature API (temperature-api/)
Вспомогательное приложение - симулятор температурных данных:
Что делает:
Генерирует случайные температурные данные (18-28°C)
Предоставляет API эндпоинты для получения температуры по локации или ID сенсора
Работает как внешний сервис для основного приложения
API эндпоинты:
GET /temperature?location=<location> - температура по локации
GET /temperature/:id - температура по ID сенсора
🏗️ Архитектура системы
Система построена по микросервисной архитектуре:
Smart Home API (порт 8080) - основной сервис
Temperature API (порт 8081) - сервис температурных данных
PostgreSQL - база данных
Docker Compose - оркестрация всех сервисов
📦 Особенности реализации
Модульная структура: handlers, services, models, db
Graceful shutdown с контекстом и таймаутами
Health check эндпоинты для мониторинга
Реальное время: при запросе сенсоров подтягиваются актуальные данные из Temperature API
Docker готовность: полная контейнеризация с multi-stage builds
Postman коллекция для тестирования API
